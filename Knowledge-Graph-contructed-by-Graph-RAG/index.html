Knowledge Graph contructed by Graph RAG

Posted on 2026-01-29 Edited on 2026-05-07

本篇文章分享一套結合 GraphRAG 與 推理式鏈結預測 (Inference-based Link Prediction) 的 Pipeline 設計，目標是將財報文字轉化為 GNN 模型可用的鄰接矩陣 (Adjacency Matrix)。

系統架構圖

本流程分為兩個主要階段：索引建構 (Indexing) 與 關係推理 (Reasoning)。

Phase 1: 建立專屬金融知識庫 (Knowledge Indexing)

利用 GraphRAG 將非結構化的財報轉化為結構化的圖譜索引。

Step 1.1: 資料前處理 (Data Preparation)

  • 輸入 (Input): 原始美股 SEC 10-K/10-Q 報告。
  • 處理 (Process): 提取核心章節（Item 1, 1A, 7），進行文字清洗與分塊。
  • 輸出 (Output): 清理後的 {TICKER}_cleaned.txt。

Step 1.2: 實體與社群檢測 (Indexing Execution)

此步驟透過 LLM 識別實體（公司、人物、技術）並利用 Leiden 演算法 進行層次化社群檢測。

  • 核心技術: Hierarchical Community Detection。
  • 產出物: 包含實體 (Entities)、基礎關係 (Relationships) 與社群報告 (Community Reports) 的 Parquet 檔案。

Phase 2: 推理式圖譜建構 (Inference-based Graph Construction)

這是研究的核心創新點，不依賴傳統的向量相似度，而是利用 LLM 對「社群摘要」的邏輯推理能力。

步驟 說明 關鍵輸出
2.1 成對組合 生成目標公司列表的所有可能配對 C(n,2) 候選清單 (Pair List)
2.2 關係推理 調用 GraphRAG Local Search 檢索相關社群背景，讓 LLM 判斷關係類型 JSON (含推理邏輯與分類代碼)
2.3 圖譜聚合 解析推理結果，轉換為結構化資料 Edge List / Adjacency Matrix

關係分類代碼定義

  1. 0: 無明確關聯
  2. 1: 供應鏈關係 (Supply Chain)
  3. 2: 競爭關係 (Competition)
  4. 3: 戰略合作 (Cooperation)

結語與展望

目前這套 Pipeline 已能穩定生成鄰接矩陣。下一步將探索如何優化查詢成本，並將此動態圖譜正式導入強化學習 (RL) 的環境狀態中。
